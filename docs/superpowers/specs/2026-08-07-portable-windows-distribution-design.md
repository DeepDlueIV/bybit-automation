# Переносимая установка Bybit Automation для Windows

## Цель

Пользователь скачивает один установщик из GitHub Releases, устанавливает приложение и запускает GUI отдельным ярлыком. Python и браузер заранее устанавливать не требуется. На чистой Windows кнопка GUI «Открыть выбранный браузер» должна запускать подготовленный браузер и позволять проверить подключение.

## Неприкосновенный эталон

- Существующие режимы `System Chrome extensions profile` и `System Chrome extensions profile (restart recovery)` не изменяются.
- Подтверждённый эталон: Google Chrome `150.0.7871.187`, Playwright `1.61.0`, BybitEye `3.0.20`.
- Эталонный запуск: отдельный процесс Chrome, отдельный постоянный профиль, динамический CDP-порт, затем подключение Playwright.
- Флаги эталона: `--remote-debugging-port`, `--user-data-dir`, `--remote-allow-origins=*`, `--start-maximized`, `--no-first-run`, `--no-default-browser-check`, `about:blank`.

## Архитектура поставки

### Установщик

- Формат релиза: Windows installer, собранный Inno Setup поверх PyInstaller `onedir`-сборки.
- Установщик содержит приложение со встроенным Python, закреплённый Chrome for Testing и подготовленное расширение.
- Установка выполняется без предварительно установленного Python или Chrome.
- Код программы устанавливается в `%LOCALAPPDATA%\Programs\BybitAutomation`.
- Изменяемые данные, логи и профили размещаются в `%LOCALAPPDATA%\BybitAutomation`.
- Установщик создаёт ярлык для отдельного запуска GUI. Запуск GUI после установки остаётся необязательной стандартной галочкой.

### Переносимый браузер

- Добавляется новый режим `Portable Chrome 150 + extensions`; существующие режимы не переименовываются и не меняются.
- Используется официальный Chrome for Testing `150.0.7871.187` для Windows x64.
- Браузер запускается самостоятельным процессом с теми же флагами и последовательностью, что эталонный System Chrome.
- Playwright подключается к уже запущенному браузеру по CDP; Playwright не управляет его первоначальным запуском.
- Профиль создаётся локально при первом запуске и никогда не входит в Git или установщик.
- На чистой установке новый переносимый режим выбирается по умолчанию. Существующие настройки пользователя не переписываются.

### Расширение

- Расширение поставляется как отдельный ресурс, а не как часть браузерного профиля.
- Для Chrome for Testing расширение загружается при запуске браузера из локального каталога ресурсов.
- Перед релизом фиксируются версия и SHA-256 расширения.
- GUI показывает отдельные статусы: браузер найден, CDP подключён, расширение загружено.
- Если автоматическая загрузка не проходит live-проверку, релиз блокируется; ручная установка не считается выполнением критерия «из коробки».

## Сборка релиза

- Репозиторий содержит только исходники, тесты, скрипты сборки и небольшие ресурсы.
- Скрипт сборки скачивает закреплённый браузер по официальному versioned URL, проверяет SHA-256 и создаёт staging-каталог.
- PyInstaller собирает приложение со встроенным Python и зависимостями.
- Inno Setup упаковывает приложение, браузер и расширение в один установщик.
- Бинарный установщик публикуется в GitHub Releases и не коммитится в Git.
- Release manifest фиксирует версии Python runtime, приложения, Playwright, браузера, расширения и их контрольные суммы.

## Диагностика

- Установщик проверяет целостность разложенных файлов, но не запускает автоматизацию.
- GUI использует абсолютные пути из централизованного runtime-конфига, а не пути машины разработчика.
- Кнопка открытия браузера создаёт профиль, запускает браузер и пишет подробный лог команды запуска.
- Кнопка проверки подтверждает версию браузера, фактический путь, профиль, CDP endpoint, доступность сайтов и состояние расширения.
- Ошибка содержит конкретный шаг, фактический путь, ожидаемую версию и путь к логу.

## Git и безопасность

- `data/`, браузерные профили, кэши, логи, cookies, настройки с паролями, `*.pyc`, `__pycache__`, `.pytest_cache`, `.venv`, `dist`, `build` и `*.egg-info` исключаются из Git.
- Перед очисткой истории создаются внешняя копия рабочей папки и полный `git bundle`.
- `data/` удаляется из всей Git-истории через `git filter-repo`; SHA старых коммитов изменятся.
- Перед force-push выполняются пробное клонирование и проверка отсутствия файлов больше 50 МиБ.
- Push выполняется только после отдельного подтверждения пользователя.

## Поэтапная реализация

1. Безопасно очистить Git и доказать, что репозиторий нормально клонируется.
2. Снять машинно-читаемый эталон рабочего System Chrome без изменения его кода.
3. Реализовать новый Portable Chrome режим и проверить его рядом с эталоном.
4. Добавить runtime-пути, preflight и диагностику чистой установки.
5. Собрать PyInstaller/Inno Setup установщик.
6. Переписать инструкцию под установщик и отдельный запуск GUI.
7. Выполнить приёмку на чистой Windows VM.

Каждый этап заканчивается отдельными тестами, live-проверкой по затронутой части, отчётом и отдельным коммитом. Следующий этап начинается только после подтверждения пользователя.

## Приёмка на чистой Windows

Начальное состояние: Windows 10/11 x64 без Python, Google Chrome и исходников проекта.

1. Скачать установщик из GitHub Releases.
2. Запустить установщик и завершить установку без ручной установки компонентов.
3. Запустить GUI отдельным ярлыком.
4. Убедиться, что выбран переносимый режим.
5. Нажать «Открыть выбранный браузер».
6. Проверить запуск закреплённого браузера, создание локального профиля и загрузку расширения.
7. Нажать «Проверить браузер» и получить успешные статусы пути, версии, CDP, сайтов и расширения.
8. Перезапустить приложение и убедиться, что локальный профиль переиспользуется.
9. Выполнить smoke-проверки реализованных функций GUI без изменения существующего System Chrome режима.

Критерий провала: необходимость вручную устанавливать Python, Chrome, переносить профиль, исправлять пути или выполнять команды в `src`.

## Отклонённые варианты

- Перенос рабочего Chrome-профиля: небезопасно, машинно-зависимо и занимает гигабайты.
- Установка последнего Google Chrome через Winget: версия меняется и не гарантирует повторяемость.
- Изменение существующего рабочего режима: запрещено, потому что он остаётся контрольным эталоном и fallback.
